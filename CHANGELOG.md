## [0.3.0] - Unreleased

### Added
- **Interface size (Settings > General > Appearance)**: 100%, 115%, 130% or 150% zoom for text and controls together, for large screens and low vision. It is applied through `QT_SCALE_FACTOR` before Qt starts, so it takes effect after a restart; a factor already set in the environment still wins, and the minimum window size is capped to the screen so a large zoom on a small display stays usable.
- **Script data lines are no longer translated; their readable words are (found on Situation Succ Inn Elysium)**: that game keeps its dialogue/sequencer scripts as text lines such as `task="0|0|false|false|ActionManager|UpdateEvidence|true"`, `line="21|1_scene_intro/21|null",` or `itemid=58,`, and they were 18,304 of its 30,828 harvested strings (59%). They were sent to the engine and came back as `görev = "..."`, which the game cannot parse, and they cost most of the run. New `src/core/harvesters/data_lines.py` leaves a line of the form `key="..."` / `key=58,` out and keeps the words a player sees inside it: the first segment of a `choice="Ask about cameras|DialogueSystem|..."` (in 94% of that game's 157 choice lines the text exists nowhere else, so it would never have been translated), `displayname`, `description` and similar keys, any sentence in an unknown key, and the text after `description="` on the first line of a multi-line value. Keys that only hold ids, scripts, conditions and paths (`task`, `line`, `name`, `conversation`, `condition`, `audiofilepath`, ...) yield nothing. Result on that game: 30,828 to 12,923 strings (58% fewer), 399 readable texts kept; 1 data-looking line remains. New setting `harvest_split_data_lines` (default on; switch under Settings > General & Language > Text Sources, 12 UI languages) and an info toast (`pipeline.data_lines_split`). Limits: the key lists and the "is this words" test are heuristics checked on this one game; a text key holding a single lower-case word in an unknown key is not recovered; a line `x = 5` in a game's own text would be dropped.
- **Asset scan in a worker process (instant Stop)**: the scenes/assets/bundles scan runs in a spawned child process (`src/core/harvesters/asset_worker.py`) that streams progress, each file's strings, its log records and the statistics back. Stop ends the child at once; before, it only took effect between files and one scene of How to Fish held the app for 26 s. Measured on three real games: the same strings as the in-process scan, Stop answered 0.06-0.09 s after the request, and the scan costs about 1.5-1.8 s more (process start). A worker that dies on its own keeps the text it had sent and the file it was on is recorded as failed; if no worker can be started, the scan runs in the main process with a warning. On Windows the worker also lives in a Job Object with a memory ceiling (70% of the free memory, at least 2 GiB; `src/utils/job_limit.py`, off when the memory protection setting is off): a file that needs more fails inside the worker (a `MemoryError`, recorded as a failed file) while the app and the PC stay responsive. Measured on How to Fish: with the ceiling at 200 MB two bundles failed and the other 56 files and all 1,100 strings were unchanged; at 120 MB 8 files failed and the scan still finished. A worker that dies on a file is replaced by one that continues after it (up to 8 times), keeping the text and statistics already sent. Where no Job Object exists (Linux, macOS) a watchdog thread in the parent polls the worker's resident memory every 100 ms and ends it above the same limit; tried on Windows with the Job Object disabled: with the limit at 160 MB the workers were ended and replaced, the scan finished and the failed files were reported (not tried on Linux/macOS). New setting `harvest_isolated` (default on; a switch under Settings > General & Language > Text Sources, 12 UI languages), a `--self-check` entry (`scan-worker`) and `multiprocessing.freeze_support()` for the PyInstaller build (not built or tried in this audit).
- **Scan diagnostics**: `harvest_report.json` lists each file's scan time and the process's peak memory at that point, and the five slowest files (`slowest_files`); a jump in the peak between two files points at the one that caused it.
- **Ignored Texts (fewer strings sent to the engine)**:
  - New `src/core/harvesters/ignore_rules.py`: after the harvest, strings matching the built-in Unity placeholders (`New Text`, `Sample text`, `Button`, `Label`, `Option A/B/C`, `Enter text...`) or the user's own rules are left out before any translation engine sees them. A toast reports how many were left out (`pipeline.ignored_text_removed`).
  - Settings card "Ignored Texts" (12 UI languages) with a switch for the built-in list and a rule box, one rule per line: plain text (whole string, case-insensitive, markup such as `<b>` is looked through), `prefix*`, or `re:regex`; `#` starts a comment. An invalid regular expression or a bare `*` is logged and skipped without disabling the other rules.
  - New settings `ignore_rules` and `ignore_engine_placeholders` (default on); the rules are read at the start of each run.

- **Text Source Switches (read less, translate less)**:
  - New Settings card "Text Sources" (General & Language tab) with one switch per harvest channel: scenes and assets, code strings (Mono / IL2CPP), loose StreamingAssets files and localization folders (12 UI languages). A channel that is off is not read at all, so its strings never reach an engine; the code channel is usually the noisiest one.
  - New settings `harvest_assets`, `harvest_code`, `harvest_streaming`, `harvest_localization` (all on by default), read at the start of each run and also for the language-dependent re-harvest. Switching StreamingAssets off also leaves loose files unpatched; with every channel off, the run finds no text.
  - `HarvestCollector(skip_channels=...)` skips channels by name (an unknown name raises `ValueError`); the encrypted-code warning is no longer shown when the code channel is off.

- **Source Labels and Bulk "Leave Out" in the Review Editor**:
  - Every harvested string now remembers the channel that produced it (scenes and assets, code, StreamingAssets, localization folders; the earlier channel wins for a string found twice). The Review Editor shows source chips with counts when more than one channel is present and filters the list by source.
  - New "Left out" status plus two actions, "Leave out shown" and "Put shown back": they apply to every row matching the current source, status and search filters (all pages) and are reversible; a left-out row returns with the status it had, and editing a left-out row brings it back.
  - Saving removes left-out rows from the game dictionary (the run had already written them, and the dictionary writer only merges), including the entries derived from them (speaker-less dialogue bodies, curly quotes, real line breaks) unless another translation still needs the same key; hand-written lines are kept. Saving is also possible when only exclusions changed.
  - This works after translation, so it does not save engine calls for that run; switching a channel off (Text Sources) or an ignore rule does. Left-out rows are not remembered by the next run.
  - New `AutoTranslatorParser.apply_translations(..., remove_keys=...)`, `ReviewSession.exclude/include/excluded`, `ReviewStore.sources/refresh_many`, `HarvestResult.sources`; "Replace in translations" respects the source filter.

- **TypeTree generator is now a default dependency (`UnityPy[ttgen]`)**: stripped MonoBehaviour TypeTrees are rebuilt from the game's own assemblies, so scenes and shared assets are read field by field instead of by raw byte scanning.
  - Measured on two Mono games (Unity 6000.x): 93-97% fewer MonoBehaviours fall back to the raw scan (6,403 to 165 and 6,024 to 450) and the harvest holds 6-22% fewer strings, the ones that disappear being GUIDs, type names, resource paths and localization keys; a sample of the removed strings held one possible UI label across both games. Cost: the harvest takes longer: 7.5 s to about 55 s for 674 MB of assets on one Mono game (7 times), and 2.8 to 13 times on the games measured later (How to Fish 2.4 s to 6.7 s after the array guard below, SkerRitual 14 s to 69 s).
  - IL2CPP is mixed: the generator could not load IL2CPP metadata v39 (Unity 6000.3 and newer) and then falls back to the raw scan with an explicit warning naming the metadata version, but on two IL2CPP games it did load and first changed the result (SkerRitual +2,294 asset strings, Shift At Midnight +196). Those extras were objects' own names (`SpellData_Fireball`, `ColorAdjustments`, `LiberationSans SDF`): with a generator attached UnityPy's `peek_name` fails ("failed to dump nodes raw"), so the raw scan no longer left each object's own `m_Name` out. The name is now read from the object's bytes (`_object_name`), and both games give exactly the same strings with and without the generator; on the Mono games the generator now only removes strings (How to Fish 1,399 to 1,100 asset strings, Twisted Party 751 to 703).
  - **Memory hazard found and fixed**: on one scene (How to Fish, `sharedassets0.assets`, 90 MB) the generator made the process hold 8.7 GB for 26 s, caused by one 1 KB MonoBehaviour whose generated tree did not match its bytes (UnityPy's native reader allocated a garbage array length). `typetree_guard.py` rejects any array longer than the bytes left in the object, so that object falls back to the raw scan; with the generator on, this game now peaks at 337 MB and takes 6.7 s. UnityPy's native reader (`UnityPyBoost`) is switched off while the generator is active so the guard sees every array; the harvest is up to about 1.8 times slower than with it (SkerRitual 39.6 s to 69 s) and produces the same strings.
  - The library prints one error line per script it cannot describe (74,584 lines for one game); these are discarded for the duration of a harvest (`src/utils/native_output.py`). Redirecting the .NET runtime's output the obvious way killed the process on the second harvest of a session (it caches its console handle), so the Windows strategy only nulls the process's standard-output handle and never closes anything.
  - PyInstaller now collects the native library and `--self-check` verifies it.

### Changed
- **Readable interface**: the colors of the three themes were measured against WCAG and raised where they fell short (muted text, control borders, and in Daylight the accent and status colors, which were 2.1-2.5:1 on white); a keyboard focus ring now follows Tab on every control; error and warning toasts stay 10 s, pause while hovered and have a real close button; every button has a screen-reader name (the editor's page buttons are announced as First/Previous/Next/Last page in all 12 languages); nothing is set below 11 px any more. The sidebar no longer moves on hover and the Patreon heart beats only under the pointer. Hard-coded colors moved into `Theme` (the amber warnings on the Dashboard and the pink support color were unreadable in Daylight), the Dashboard uses the shared `PrimaryButton`/`SecondaryButton` instead of its own copies, button labels and icons are centred (the content of `PrimaryButton`, `SecondaryButton`, the segmented toggle and two Dashboard buttons sat off to one side and could be clipped), and a text setting now shows a check after it saves and puts back the value the backend actually kept when it trimmed, clamped or refused the edit.
- **Completion window buttons in a 2 x 2 grid**: the four buttons (Start game, Review in editor, Open patch folder, Close) shared one row and elided their labels in the narrow dialog ("Oyunu Ba...", "Editörde İnc..."). They now sit two per row, each with room for its whole label (checked in Turkish and German); without a game executable the closing button takes the whole last row.
- **Plainer settings texts (12 languages)**: the labels and descriptions of the memory protection, the separate scan process, the script-line option, Code strings, "Also patch StreamingAssets files", the TextMeshPro font override and the aggressive Google retry were rewritten for non-technical readers (what it does, what happens with it on or off). The memory protection now reads "Protect my PC from running out of memory" and says its strict limit works together with the separate-process option. "Also patch StreamingAssets files in place" is now disabled, with an amber note, while "Loose data files (StreamingAssets)" is switched off, because with that source off no loose file is read and the option could do nothing.
- **Tests**: 903 passing tests on Python 3.10, 3.12 and 3.14 (0.2.0: 532; 3 more run only on other platforms or with an optional library), including a shared hand-written UnityFS bundle builder that is checked against UnityPy (`tests/bundle_factory.py`). One existing locator test now uses a folder of its own: the locator also scans around the data folder, so it picked up the bundles other tests had written next to it.
- **Documentation**: the `AGENTS.md` directory tree lists the new modules (`ignore_rules`, `text_encoding`, `xml_text`, `bundle_header`, `bundle_unpack`, `memory_guard`, `native_output`).

### Fixed
- **Games built with Unity 6000.5 crashed about 13 s after launch once the patch was installed (found on Situation Succ Inn Elysium, Unity 6000.5.2, Mono)**: the player died with an access violation inside `UnityPlayer.dll` while "Loading [XUnity Auto Translator]". A probe plugin that logs after each Unity call showed the cause: calling `StartCoroutine` while BepInEx loads the plugins (before the player loop runs) kills Unity 6000.5.2, and XUnity's start-up starts a coroutine. It crashed with XUnity 5.6.2 and the latest 5.6.3.1 alike, whatever the configuration (every text framework off, MonoMod hooks, fonts cleared, UI Toolkit hooks off); BepInEx alone and the Resource Redirector alone ran fine. New `src/core/hook_manager/delayed_start.py` replaces XUnity's BepInEx 5 wrapper by `xunity_wrapper/XUnity.AutoTranslator.Plugin.BepInEx.dll`, built from `xunity_wrapper/DelayedStart.cs` (MIT, derived from XUnity 5.6.2's wrapper; build with `tools/build_xunity_wrapper.py`): same plugin identity, but `PluginLoader.LoadWithConfig` runs from `Update()` after three frames. It is applied for Mono games on Unity 6000.5 and newer, at install time and to an install made earlier (every run now checks, also when nothing needs installing), and on any other Mono game whose last BepInEx log ends while XUnity was loading (the signature of this crash on a version not yet in the list): the next run switches the wrapper and a warning toast says to start the game again (`installer.delayed_start_after_crash`, 12 languages; the first launch of such a game still crashes once), only over the exact 5.6.2 wrapper or an earlier copy of ours (a hand-installed XUnity of another version is left alone, with a warning), the shipped DLL is checked against its SHA256 first, and the original stays next to it as `.bak`. Measured on that game: 75 s without a crash, XUnity logged "Loaded XUnity.AutoTranslator into Unity [6000.5.2f1] game", TextMesh Pro hooks and the fallback font loaded. Not verified: the translated text on screen with the shipped build, other Unity versions below 6000.5 (the threshold is 6000.5.0 because 6000.5.2 is the only version seen crashing), IL2CPP games on 6000.5, Linux.
- **Syntax Guard now protects game directives in square brackets (`[pic=39]`, `[picc=12]`, `[wait=0.5]`)**: only NGUI colour/style tags were protected, so an engine turned `[pic=39]` into `[resim=39]` and the game would not recognise it (4,214 strings of the game above carry such a tag). A name, `=` and a short value without spaces inside brackets is a protected token; `[Charm]`, `[Strength 5]` and NGUI tags are unchanged. A real translation of 25 tagged strings with the fix kept every tag.
- **The game behind the 0.2.0 report (Situation Succ Inn Elysium 1.1.6, Unity 6000.5.2, 21 GB) now scans in about 20 s with 210 MB**: 92 asset files (the "82/92" of the report) including 12 Addressables bundles of 0.26 to 4.0 GB (LZ4HC, 128 KB blocks) that unpack to 4.1 GB at most. Their readable part is a 17 KB serialized file next to a multi-hundred-MB `.resource` stream, so the estimated peak per bundle is about 0.5 MB where the 0.2.0 path needed about twice the unpacked size (8 GB for the largest, with 3 GB free on the test machine). 28,979 strings, nothing skipped. The 0.2.0 run itself was not repeated on this PC (it would have made it swap), so that the hang had this cause remains an inference from the sizes. `UnityPy` 1.25.3 fails on this game's Unity 6000.5 serialized files in every bundle ("iterative unpacking requires a buffer of a multiple of 32 bytes"; the old whole-bundle path fails the same way); 1.25.4 reads them, so `requirements.txt` now asks for `UnityPy[ttgen]>=1.25.4`.
- **Ignored Texts regular expressions could hang or wipe the harvest (found in the 0.3.0 audit)**: a rule that matches empty text (`re:` while it is being typed, `re:.*`, `re:x*`) removed every string, and `re:(a+)+$` took 79 s on a 30-character text with Stop unable to interrupt it. Such rules are now refused with a log entry, a repeat nested in an unbounded repeat is refused, a regular expression only sees the first 1000 characters of a string, and `re:` is recognized in lowercase only (`Re: Hello` is plain text). Limit: other catastrophic shapes such as `(a|aa)+` are not detected.
- **Encoding detection**: a short file in the source language's own code page (Polish cp1250 with source `pl`) was read as Windows-1252 when the detector gave no answer; the language's code pages are now tried directly. A file whose encoding is only the detector's guess (no mark, not UTF-8, not one of the source language's code pages) is logged as a warning.
- **LZMA bundles with several files**: each wanted file used to decode the block again from its start; the decoder now continues where the previous file stopped (unit-tested; the speed-up was not measured on a real bundle).
- **Scan stuck for hours and system disk full on games with large AssetBundles (reported on 0.2.0)**: UnityPy unpacks a compressed bundle completely in memory, including the textures and audio streams the harvest never reads. Measured, a scan peaked at about twice the unpacked size of a bundle (a bundle that unpacks to 1 GiB cost 2.1 GiB). A bundle that does not fit in RAM makes Windows grow its paging file on the system disk and the whole PC crawl; the application itself writes next to nothing to disk during a scan.
  - **Bundles are no longer unpacked whole.** `bundle_header.py` reads the block and file tables of a UnityFS bundle from its header (in well under a millisecond; it matches UnityPy byte for byte, LZ4, LZ4HC, LZMA and uncompressed, format 6 to 8, blocks info at the start or the end, with and without the padding flag), and `bundle_unpack.py` unpacks only the files that can hold text, one at a time; `.resS` and `.resource` streams stay packed. LZMA, one long stream, is decoded in pieces and abandoned once the file is complete. The harvest result is unchanged: the same strings on all 117 bundles of six installed games (17 with text), and on every whole-game scan.
  - Measured with the real harvest: a text-bearing bundle with a 1 GiB stream went from 2153 MiB to 100 MiB (0.5 GiB LZMA stream: 100 MiB); a bundle costs twice its largest file that holds objects, not twice the bundle. Scans are also faster (garbage collection now only follows files of 8 MiB and more, it cost about 50 ms after every small file): How to Fish 5.8 s to 1.2 s, SkerRitual 21 s to 13.6 s.
  - What is not unpacked this way (other bundle formats such as `UnityWeb`/`UnityRaw`, encrypted bundles, unreadable headers) is still opened whole and protected by `memory_guard.py`, which compares the expected peak with the memory that is free right now and skips a file that would use more than 70% of it. A skipped file is never silent: a warning notification names it with its size (`pipeline.harvest_warn_oversized`), `harvest_report.json` lists it with its size, expected peak and the free memory, and the log says why. The Toolbox asset scan reports it too.
  - The progress line now shows the size of the file being scanned ("Scanning asset files (82/92): name (3.2 GB)"), so a long step can be recognized. New setting "Skip asset files too large for memory" (Settings > General & Language > Text Sources, on by default) for users with plenty of RAM or virtual memory; `psutil` is now a declared requirement (it was already installed through `py7zr`) and part of `--self-check`.
  - Known limits: the text inside a skipped file is not translated; a serialized file that is itself huge still costs about twice its size; Stop still only takes effect between files; the estimate for bundles opened whole is derived from the file size (assumed 3x unpacking), not measured.

- **Loose files in Shift-JIS, GBK, Big5, EUC-KR, Windows code pages and UTF-16**: they were read as UTF-8 with replacement characters, so their "text" was `�` garbage sent to the engine (Shift-JIS, GBK, cp1251 and cp1252 files yielded no usable string, UTF-16 files had a zero byte between every letter), and patching them dropped every non-ASCII byte of the untranslated lines (`errors="ignore"`) and rewrote the file as UTF-8.
  - New `src/core/parsers/text_encoding.py` detects the encoding (byte-order mark, strict UTF-8, then `charset-normalizer`; UTF-16 without a mark by its zero bytes) and every patched file is written back in the encoding and byte-order mark it had; untranslated lines keep their exact bytes.
  - `charset-normalizer` is unreliable between look-alike single-byte code pages and for short CJK files (it called short GBK "Korean" and Western text cp1250, cp775 or "Czech"), so Latin files settle on Windows-1252 and the source language picks the code page (Shift-JIS/EUC-JP, GBK/Big5, Korean, Windows-1250/1251/1253-1258, KOI8). Polish, Turkish or Baltic files therefore decode as Windows-1252 until the detected source language is known and the harvest is repeated with it.
  - A file whose encoding cannot be determined is skipped with a log entry, never guessed or rewritten; a translation containing characters the file's encoding cannot hold (Turkish into Shift-JIS, for example) leaves the file unpatched with a warning (the runtime dictionary still translates the text in game).
  - Also covers `.nani` scripts, which now get the source-language hint too. `charset-normalizer` is now a direct requirement (it was already installed through `requests`) and part of `--self-check`.

- **XML patching kept less of the file than it should**: loose `.xml` files were rewritten through the standard library's ElementTree, which dropped every comment, replaced `<![CDATA[...]]>` sections by escaped text and forgot unused namespace declarations.
  - New `src/core/parsers/xml_text.py` (lxml): only the translated words change. Comments, processing instructions, CDATA sections, namespace declarations, attribute order and an external DOCTYPE stay; a translated CDATA leaf stays a CDATA section; the text that follows a comment is still translated while the comment's own text never is. Harvest results and their order are unchanged.
  - The document is parsed from UTF-8 bytes with the declared encoding overridden (lxml refuses `str` input with an encoding declaration), the original XML declaration is written back as it was, and documents with entity declarations are still refused (no entity expansion, no DTD loading, no network).
  - Known cosmetic difference: the line break between a top-level comment and the root element is not kept. `lxml` is now a direct requirement and part of `--self-check`.

- **Syntax Guard placeholder coverage**:
  - Unity Localization Smart Strings with a nested group (`{0:plural:{} coin|{} coins}`, `{0:{1}}`) are protected as one token; before, the `{}` inside made the whole item unmatched, so engines could rewrite the structure and the integrity gate saw nothing to compare.
  - Positional printf specifiers (`%1$s`, `%2$d`) and the TextMeshPro `<margin-left>` / `<margin-right>` tags are protected.
  - Protected and glossary terms now match inside Japanese, Chinese, Korean and Thai text; `\w` covers kana and Han, so names such as `アルス` in `アルスは勇者だ` were never protected. Latin terms still stop at word boundaries, but may touch kana or Han.
  - Token recovery after machine translation also accepts a complete full-width / CJK / guillemet bracket pair (`［ULPH_0］`, `【ULPH_0】`, `«ULPH_0»`), `ULPH 0` inside brackets, and a bare `ULPH_0`. A lone bracket is never consumed, so legitimate quotes next to a mangled token survive; anything still unrecovered is rejected by the integrity gate.
  - Known limit: a Smart String protected whole keeps its inner words (`coin|coins`) in the source language.

## [0.2.0] - 2026-10-26

### Added
- **Automatic Source-Language Detection**:
  - New `src/core/lang_detect/` package resolves `Auto-detect` before translation starts: Unicode script analysis (Han, kana, Hangul, Thai, Hebrew, Greek) → offline `py3langid` model (≥ 90% confidence over a spread of prose lines) → Google majority vote for keyless engines (Google/Bing; users of private or paid engines never send text to Google).
  - The detected code now drives the engine request, CSV/TSV column selection (loose tables are re-harvested when the language differs from English) and XUnity `FromLanguage`, so Chinese, Japanese, Korean and Russian games no longer run as "assumed English".
  - Detector answers are mapped to the language catalog (`canonical_language_code`: `zh` → `zh-CN`, `iw` → `he`, ...); the Google mirrors gained a `detect_language` call for the online vote.
  - When a game only ships non-English Unity Localization tables, the locale of those tables is used as the source language (`source_detected_tables` notice), and the harvest is repeated for that language whenever table or record content depends on it.
  - `py3langid` added to requirements, PyInstaller collection and `--self-check` (which also verifies the offline model).
- **Automatic Runtime Setup (no install button)**:
  - "Start translation" now checks and, when needed, downloads and installs the matching BepInEx + XUnity package for the game's Mono/IL2CPP flavor and 32/64-bit build (SHA256-pinned downloads) and shows only a "preparing components" status. The manual install buttons were removed from the Dashboard and Toolbox (uninstall stays).
  - `BepInEx/UnityLocalizer.runtime.json` records the installed package; a hand-installed hook of the right generation is kept, a mismatching one is replaced. After a run, `BepInEx/LogOutput.log` is inspected ("Chainloader startup complete", XUnity, `[Fatal]`/`[Error]`) and the result is reported.
  - Clear, localized failure reasons (network, integrity, permission, unsupported build) instead of a generic error; a build whose bitness could not be determined is flagged.
- **Dashboard Notices Card**: warnings and important results (language detection, unreadable files, glyph coverage, runtime log, Proton/Linux hints, anti-mod detection) are shown on the Dashboard (Turkish tab name "Ana Sayfa"), not only in the log; the card is cleared when a new run starts.
- **Harvest Coverage Report & Deeper Extraction**:
  - `HarvestStats` records files scanned or failed, raw-scanned objects, Unity Localization tables matched or skipped by locale, I2 sources and encrypted code; a summary is written to `harvest_report.json` and unreadable files, raw scans and encrypted code raise warnings.
  - New `localization` channel for loose folders named like `Localization`, `Lang`, `Dialog`, `Text`, `i18n`, `Subtitle`, `Story`; extra AssetBundles (`.bundle`, `.unity3d`, `.assetbundle`, `.ab` with UnityFS magic), `mainData`, `.split0` parts; subtitles (`.srt`) and .NET resources (`.resx`); single CJK characters in menus; JSON with raw line breaks inside strings.
- **Source-Language Filtering of Multi-Language Games**: JSON records that carry every language side by side (`english_text`, `chinese_text`, `korea_text`, ...) keep only the source-language field, and strings in a script foreign to the source language (Cyrillic, Han, kana, Hangul, Thai...) are left out, with a guard that keeps everything and warns when the source-language setting looks wrong. Project XX Queen: 94,017 → 17,891 strings.
- **Anti-Mod Warning**: some games ship code that deletes BepInEx at start (Project XX Queen Demo has `BepInExRemover` / `CheckAndRemoveBepInEx`: the folders vanish about 10 seconds after launch and the game quits, so no translation can appear). The pipeline reads class and method names from `Assembly-CSharp*.dll` / `global-metadata.dat` before translating and warns in 12 languages. Detection is read-only; the tool does not work around the game's protection.
- **User Notifications for Important Events**:
  - Progress events listed in `NOTIFICATION_LEVELS` now raise a toast and a warning/info log entry: detected game language (offline or online), failed detection, unknown Unity version and missing font glyphs.
  - Source-language label simplified from "Auto-detect (assumes English)" to "Auto-detect" in all 12 UI languages.
- **Universal Multi-Theme & Accent Preset UI System**:
  - Introduced unified reactive QML theme singleton (`Theme.qml`) implementing the 3-theme token matrix: **Obsidian** (Default Dark), **Daylight** (Soft White), and **Cyber Neon** (High-Contrast Glow).
  - Integrated 4 distinct accent color presets: **Cyan/Teal** (Modern), **Emerald/Mint** (Nature), **Indigo/Violet** (Creative), and **Amber/Orange** (Energetic).
  - Developed reusable UI archetype components (`PrimaryButton.qml`, `SecondaryButton.qml`, `SegmentedToggle.qml`, `SectionCard.qml`, `QuickTag.qml`).
  - Refactored all views (`Main.qml`, `DashboardView.qml`, `ToolboxView.qml`, `SettingsView.qml`, `ConsoleView.qml`, `EditorView.qml`, `AboutView.qml`) to eliminate hardcoded palette properties in favor of semantic tokens.
  - Added interactive Appearance & Theme management card in Settings, with full i18n coverage across all 12 supported languages.
- **High-Performance In-Memory Regex Caching & FairyGUI Support**:
  - Activated `CacheRegexPatternResults=True` in BepInEx AutoTranslator configuration, caching compiled regex outcomes in memory to prevent micro-stuttering and preserve 60+ FPS during heavy text scenes.
  - Lowered `MinDialogueChars=1` to capture single-character menu buttons (`+`, `-`, `X`, `?`, `!`, `1`).
  - Added native `EnableFairyGUI=True` framework hooking for Asian and mobile-ported Unity titles.
- **Runtime Glossary Terminology Injection (`_Substitutions.txt`)**:
  - Automated deployment of user glossary terms to `Translation/{Lang}/Text/_Substitutions.txt`.

### Fixed
- **Linux: starting the game from the app**: the completion dialog's launch button ran the game binary directly, which never loads BepInEx on a native Linux game. It now starts `run_bepinex.sh` when the hook is installed, and a Windows game on a Linux host gets a clear message (start it from Steam with Proton) instead of a raw error (`game_launcher.py`).
- **Linux: TextMeshPro fallback font names**: the automatic fallback used Windows font names (Arial, SimHei, Meiryo, Malgun Gothic, Segoe UI), which a Linux or Steam Deck system does not have. Native Linux games now get Linux families (DejaVu Sans, Liberation Sans, Noto Sans, Noto Sans CJK, ...), chosen from the installed fonts when `fc-list` is available (`system_fonts.py`).
- **Patch scripts hid failures**: `Install_Patch.sh` and `Uninstall_Patch.sh` copied files in a loop at the end of a pipe, so a failing `cp` did not stop the script and it reported success. They now count failures, print each one and exit non-zero (tests run the generated scripts with a real `sh`).
- **Uninstall left the install behind**: the runtime marker now lists the top-level files and folders the installer added, and uninstall removes exactly those (`.doorstop_version`, the bundled `dotnet/` runtime of IL2CPP installs, proxy files); older installs are cleaned only for what is certainly BepInEx's. BepInEx's own `changelog.txt` is no longer extracted, so it cannot replace a game file of the same name.
- **IL2CPP games showed no translation at all**: `AutoTranslatorConfig.ini` was written with `ForceMonoModHooks=True`. XUnity's IL2CPP text hooks exist only as Harmony hooks, so every hook failed ("Harmony is not supported in this runtime"). The setting is forced to `False` (existing installs are corrected on the next run); extra `behaviour` keys no longer replace the other forced Behaviour keys. `EnableTranslationScoping=False` and `IgnoreVirtualTextSetterCallingRules=True` stay forced to bypass TextMeshPro virtual setter constraints on modern .NET runtimes.
- **No TextMeshPro font for Turkish and other Latin-extended text**: the Settings default (empty system font) was passed as `""`, which switched the font override off instead of choosing one automatically, so IL2CPP games kept a font without `ç ğ ı ş ö ü`. Empty now means automatic (see the IL2CPP fallback font above); a value written by an older run is cleared. Verified in Project_Dungeon (`ı ğ ç ö` render, no crash).
- **Texts with a stored `\n` stayed untranslated**: some games keep line breaks as the two characters backslash + n and convert them just before drawing, so XUnity saw a real line break and never matched the dictionary key. Every such entry now also gets a real-line-break variant (143 entries in Project_Dungeon, verified in game).
- **Runtime templates dropped at random**: only 1500 regex entries were written and the survivors were simply the first ones harvested, so in Project_Dungeon 1736 of 3236 placeholder templates and all 7357 choice-prefix entries were lost. The cap is now 3000 (measured: negligible load cost; the game started and translated as before).
- **Doubled icons and ⚠ prefixes**: the `export_patch_btn` and `harvest_assets_btn` strings carried a 📦 emoji although their buttons already draw a Lucide icon; the `quick_rtl_*` and `quick_lang_unsupported` strings carried ⚠/↔ prefixes. They are gone from all 12 locales.

## [0.1.0] - 2026-10-19

Initial open-source release of **UnityLocalizer**, an autonomous desktop translation and localization automation suite for games built on the Unity engine.

### Added
- **Multi-Channel Text Harvesting**:
  - Read-only asset extraction using `UnityPy` across `level*`, `*.assets`, `data.unity3d`, and loose/Addressable `AssetBundle` archives.
  - TypeTree-aware field extraction for Unity Localization (`StringTable`), I2 Localization (`LanguageSourceData`), and Pixel Crushers `DialogueDatabase`.
  - Static IL2CPP string literal pool harvesting from `il2cpp_data/Metadata/global-metadata.dat`.
  - Static Mono assembly string literal extraction from the `#US` (User String) stream of `Managed/Assembly-CSharp.dll` without executing game binaries.
  - Loose `StreamingAssets` parsing for JSON, CSV, TSV, XML, plain text, Yarn Spinner (`.yarn`), Inkle Ink (`.ink.json`), and Naninovel (`.nani`) scripts.
  - Shared heuristic text filter (`harvesters/text_filter.py`) automatically skipping code identifiers, GUIDs, shader names, namespaces, and technical asset paths.
- **AST Syntax Guard & Placeholder Isolation**:
  - Tokenization and strict preservation of Unity RichText tags (`<color>`, `<size>`, `<b>`, `<i>`, `<sprite>`), NGUI BBCode (`[ff0000]`), and C# string formatting patterns (`{0}`, `{playerName}`, `\n`, `%s`).
  - Automated word-boundary token repair for dropped standalone placeholders.
  - Multiset integrity gate preventing broken tags or format mismatches from corrupting game logic.
- **Autonomous Runtime Hook Deployment (Route 3)**:
  - Automated deployment of BepInEx 5.4.23.5 (Mono) or BepInEx 6 (IL2CPP; v6.0.0-pre.2 for metadata v23–v29, Bleeding-Edge build 764 for Unity 6 / metadata v30+).

  - Version-matched ArialUnicode SDF fallback font bundle provisioning to `BepInEx/font/` resolving missing TextMeshPro glyphs ("tofu" boxes).
  - Dynamic `.NET` regex dictionary generation (`r:"pattern"="replacement"`) in `UnityLocalizer.txt` translating formatted runtime strings (`Gold: {0}`).
  - Non-destructive `AutoTranslatorConfig.ini` line-preserving merge updating only managed keys while preserving user custom configurations.
